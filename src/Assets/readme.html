Presentation mode

Текущий путь композиции выбранного swap chain

PresentMode

Источник: PresentMon PresentMode
Present

Категориальное raw-поле PresentMon для последнего кадра выбранного swap chain. Показывает, каким presentation path Windows доставляет кадр: independent flip, composed flip, legacy flip и другие документированные режимы.

Значение выводится напрямую из PM_METRIC_PRESENT_MODE; усреднение и пользовательская формула не применяются. При изменении режима окно старых samples очищается, поэтому числовые агрегаты не смешивают разные presentation paths.
Для низкой задержки обычно важны Hardware: Independent Flip и Hardware Composed: Independent Flip; Composed: Flip означает участие DWM в композиции.

CPU pipeline

Покадровые CPU-поля PresentMon

Average MsBetweenAppStart

Источник: PresentMon MsBetweenAppStart
CPU

Среднее время от начала CPU-работы над текущим application frame до начала CPU-работы над следующим frame.

Formula
Average=∑i=1NMsBetweenAppStartiN
Показывает общий CPU frame cadence приложения. Меньше: чаще начинается обработка новых кадров.

Average MsCPUBusy

Источник: PresentMon MsCPUBusy
CPU

Среднее время, которое CPU работал над кадром до вызова Present().

Formula
Average=∑i=1NMsCPUBusyiN
Меньше: приложению требуется меньше активного CPU-времени для подготовки кадра к Present().

Average MsCPUWait

Источник: PresentMon MsCPUWait
CPU

Среднее время ожидания CPU перед началом следующего кадра.

Formula
Average=∑i=1NMsCPUWaitiN
Отражает ожидание между CPU frames, включая pacing, блокировки и ожидание доступности следующей работы.

Stutter analysis

CapFrameX-классификация по сырому ряду PresentMon MsBetweenPresents

Stutter Time % [CapFrameX]

Источник: PresentMon MsBetweenPresents; метод: CapFrameX
Analysis

Процент суммарного времени окна, пришедшийся на кадры, классифицированные как статтеры алгоритмом CapFrameX. Используется тот же набор stutter-флагов, что и для Stutter Frames [CapFrameX].

Classification
xi>2.5×Bi
Formula
StutterTime%=100×∑stutter ixi∑i=1Nxi
x = MsBetweenPresents. Размер trailing moving-average окна: Convert.ToInt32(10 × sqrt(mean(x))). При построении baseline значение, превышающее предыдущее более чем в 3 раза, заменяется предыдущим значением: это повторяет SampleBasedMovingAverage CapFrameX.
Меньше: меньшая доля измеренного времени была потеряна на выраженные frametime-выбросы. 0.00 % означает, что в текущем окне алгоритм не классифицировал ни одного кадра как stutter.

Stutter Frames [CapFrameX]

Источник: PresentMon MsBetweenPresents; метод: CapFrameX
Analysis

Число кадров текущего окна, удовлетворивших CapFrameX-условию статтера, и общее число валидных значений MsBetweenPresents.

Display
StutterFrames=#{i:xi>2.5×Bi}N
В оверлее выводится формат stutter frames / total frames, например 3 / 239. Классификация вычисляется один раз и совместно используется обеими CapFrameX-метриками.
Показывает частоту явных frametime-выбросов. Для оценки тяжести событий рассматривай вместе со Stutter Time % [CapFrameX].

Display / latency

Путь Frame Start → Display, Present → Display и фактическая смена кадров

Average DisplayLatency

Источник: PresentMon DisplayLatency
Display

Среднее время от начала обработки application frame до фактического отображения этого кадра на экране. Значение поступает напрямую из PM_METRIC_DISPLAY_LATENCY; отдельные CPU/GPU/present интервалы вручную не складываются.

Formula
Average=∑i=1NDisplayLatencyiN
Используются конечные неотрицательные значения displayed application frames текущего swap chain. Единицы нормализуются в миллисекунды через PresentMon introspection metadata.
Меньше: короче полный измеряемый путь кадра от начала CPU frame до экрана. Это frame-to-display latency, а не физическая mouse-to-photon latency.

SD DisplayLatency

Сырой ряд: PresentMon DisplayLatency
Display

Population standard deviation покадровых значений DisplayLatency в текущем окне.

Formula
SD=∑i=1N(xi−x¯)2N
x = DisplayLatency; используется population denominator N и однопроходный алгоритм Welford.
Меньше: стабильнее общий уровень frame-to-display latency внутри окна.

RMSSD DisplayLatency

Сырой ряд: PresentMon DisplayLatency
Display

Корень из среднего квадрата разностей между соседними конечными неотрицательными значениями DisplayLatency в порядке захвата.

Formula
RMSSD=∑j=1K(xj−xj−1)2K
x = DisplayLatency; K: число валидных соседних пар; 0 ms допускается как неотрицательное raw value.
Меньше: меньше резких покадровых изменений полного frame-to-display latency.

Displayed Stepwise-Relative

Сырой ряд: PresentMon MsBetweenDisplayChange; формула: project-defined
Display

Среднее абсолютное относительное изменение между соседними положительными значениями MsBetweenDisplayChange в порядке захвата. Предыдущее displayed-frame interval используется как база сравнения.

Formula
StepwiseRelative=100×1K∑j=1K|xj−xj−1|xj−1
x = MsBetweenDisplayChange; K: число валидных соседних пар. Пары с предыдущим значением <= 0 исключаются. Это производная метрика проекта, а не отдельное raw-поле PresentMon.
Меньше: соседние displayed-frame intervals изменяются более равномерно относительно собственного уровня. Метрика дополняет абсолютный RMSSD MsBetweenDisplayChange процентной нормализацией.
